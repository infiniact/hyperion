# AI 共建 —— 最小可售形态（MVP）产品 + 商业化拆解

> 范围：把现有 `events/bedwars` 原型沉淀为一个**可售产品**，并给出两条 GTM 假设、计费/配额设计、打包边界与上线里程碑。
>
> 标注约定：**[事实]** = 代码中已验证；**[估算]** = 基于事实的量化推测；**[假设]** = 待验证的商业判断。
>
> 底座（直接采用，不论证）：hyperion（Rust/Bevy ECS 的 MC 引擎，能扛 1000+ 人）+ iacoder（公司自研基石 agent，全部产品基于它，能力完全自控，在 `../iacoder`）。

## 1. 产品定位与边界

### 1.1 一句话定位
**"AI 共建" = 玩家用自然语言指挥 AI 在一个会被永久保存的 MC 世界里对话与建造。**

### 1.2 可售产品 vs 引擎底座

| 层 | 内容 | 属性 |
|---|---|---|
| **引擎底座（不卖，开源）** | hyperion 内核：网络/ECS/区块/`Blocks` 运行时编辑 API、`persist.rs` 持久化机制 | 开源资产，是护城河的"地基"但不直接计费 |
| **可售产品（MVP 核心单元）** | `/ai` 助手 + AI NPC + AI 建造（say/place/fill）+ 建造持久化 + 配额/计费/防滥用 | 围绕 token 成本计费的那一层 |
| **私有能力（iacoder）** | agent loop、provider 抽象、工具编排、会话历史 | 闭源，能力自控，是"为什么别人抄不动"的核心 |
| **可选增值 / demo** | 真实天气灾害、自驱动动物、步步生莲 | 营销 demo 与高价档点缀，不进 MVP 关键路径 |

### 1.3 MVP 砍到哪：核心三件 + 论证

**核心可售单元（MVP 必含）：AI NPC + AI 建造助手 + 建造持久化。**

为什么是这三件而不是别的：
- **三者构成一个完整的价值闭环**：NPC 是"低门槛入口"（不用记命令，右键就能聊）；建造助手是"核心动作"（自然语言→世界改变）；持久化是"价值留存"（玩家的共建成果不会重启即焚，否则建造毫无意义）。少任何一个，付费理由都不成立。 **[假设]**
- **三者都已是"原型可用"而非 demo**，工程风险最低（见 §0 表）。
- **三者的成本可被单一变量（token）解释**，计费模型干净（见 §3）。

**天气/动物/步步生莲砍为可选增值或 demo**，理由：
- 它们是**表现层奇观**，不构成"付费才能解锁"的硬价值——服主可以用别的插件做天气，玩家不会为"会漫步的猪"订阅。 **[假设]**
- 但它们是**极强的录屏/直播素材**（真实台风打进游戏砸塌建筑），价值在 GTM 漏斗顶端拉新，不在变现，所以留作 demo/高价档点缀，不占 MVP 工程预算。
- 天气 demo 还自带上线阻碍（中文硬编码、坐标写死，见 §5），更不该进关键路径。

**边界红线**：MVP 不做 PvP/小游戏玩法（bedwars 的 attack/bow/team 等是引擎演示，不是本产品）；不做世界编辑器 GUI；不做多世界编排（先单世界跑通）。

## 2. 两条 GTM 假设（各一版）

### 2.A B2B：卖给现有 MC 服主的插件 / 托管 SaaS

- **目标客户**：已有玩家基础、想加"新鲜玩法"留存的中小型生存/创造服服主（社区服、QQ/Discord 群服）。 **[假设]**
- **差异化卖点**：
  1. **"会动手的 AI"**——市面 MC AI 插件多是聊天机器人；本产品的 AI 能真正改世界（place/fill）且**成果持久化**。 **[假设]**
  2. **engine 级性能**——hyperion 能扛 1000+ 人，AI 建造走运行时 `Blocks` API 而非逐包模拟，适合大服。 **[事实（性能前提）] + [假设（对服主的吸引力）]**
  3. **成本可控**——内置冷却（40 tick）+ fill 上限（16384）+ 配额，服主不会被 token 账单吓到。 **[事实]**
- **为什么愿付费**：服主的痛点是"留存"和"差异化"，AI 共建是可营销的卖点；且把"接 LLM、控成本、防滥用"这件麻烦事外包给我们。 **[假设]**
- **形态**：两条腿——(a) 自托管插件（服主自带 API key），(b) 全托管 SaaS（我们代管 sidecar + key + 配额）。

### 2.B B2C：AI 共创创意服订阅

- **产品**：一个我们自营的、玩家与 AI 共建持久世界的创意服，按月订阅。 **[假设]**
- **卖点**：零门槛建造（不会红石/不会盖楼也能造城）、世界永久保存、可炫耀的"我和 AI 一起盖的"作品。
- **为什么愿付费**：为"创造的即时满足感"付费，类似 AI 绘画/AI 写作的 C 端付费逻辑。 **[假设]**
- **风险**：获客成本高、留存未知、需要内容运营，且**我们直接承担全部 token 成本**。

### 2.C 哪条先做 MVP —— 选 **B2B（先自托管插件）**

理由：
1. **验证成本最低**：B2B 自托管让**服主承担 token 成本**，我们先不背 LLM 账单，能在零边际成本下验证"有没有人要"。 **[事实（成本归属）] + [假设（验证逻辑）]**
2. **现有原型几乎就是 B2B 形态**：bedwars 已是"装进 hyperion 的插件集合"，距离"可分发插件"最近。 **[事实]**
3. **B2C 需要先有运营和留存数据**，本质是 B2B 跑通后的"自己当自己的客户"——可作为第二步（用同一套产品开自营服）。
4. **付费意愿信号更清晰**：服主是理性买家，愿不愿付、付多少，反馈比 C 端冲动消费更可量化。

> 结论：**MVP = B2B 自托管插件**；全托管 SaaS 与 B2C 创意服作为验证通过后的 phase 2。

## 3. 计费与配额设计

### 3.1 计费点取舍

| 计费点 | 适配 | 评价 |
|---|---|---|
| 按 token 实计 | 全托管/重度用户 | 最贴成本，但对服主不可预测、难解释 |
| 按 AI 调用次数 | 通用 | 直观，但一次"盖座城"和一句"你好"的 token 差几十倍，单价难定 |
| 按席位（同时在线玩家/月活） | B2B | 可预测，但与 token 成本脱钩，重度服会亏 |
| 订阅档（含额度，超量加购） | **MVP 推荐** | 可预测 + 成本封顶兼得 |

**MVP 采用：订阅档 + 内含 token 额度 + 超量按包加购**。把"线性的 token 成本"包进"阶梯式的订阅档"，对客户可预测，对我们成本可控。

### 3.2 token 成本透传 / 封顶

- **自托管档**：服主自带 key（`config.toml` 的 `${ENV:VAR}` 已支持） → 成本**完全透传**，我们只收平台/授权费。 **[事实]**
- **托管档**：我们代管 key，按"内含 token 额度"封顶；额度耗尽则降级（仅 NPC 闲聊、禁建造）或提示加购。
- **每次回合上限**：`MAX_TURNS=8` 已限制单回合工具轮数 **[事实]**；建议追加**单回合 token 上限**与**单玩家日额度**（当前无，属待建，见 §5）。

### 3.3 免费 vs 付费 + 防滥用

- **免费额度**：每服每日 N 次 AI 建造 + 不限量 NPC 闲聊（闲聊 token 小）。用于让服主先体验。 **[假设]**
- **防滥用（可复用现成机制）**：
  - NPC 40 tick 冷却 **[事实]** → 扩展为**每玩家通用速率限制**。
  - fill ≤ 16384 方块 **[事计]** → 防"填满世界"的成本爆炸。
  - 建议补：每玩家/每服**日 token 配额**、滥用词过滤、建造区域白名单（防 AI 拆别人建筑）。

### 3.4 定价档位草案 **[假设 —— 数字待用真实 token 单价校准]**

| 档位 | 形态 | 价格/月 | 内含额度 | 适合 |
|---|---|---|---|---|
| Free | 自托管 | $0 | 每日 20 次 AI 建造，NPC 闲聊不限 | 试用 |
| Self-Host Pro | 自托管（自带 key） | $19 | 无平台额度上限（token 自付） | 想完全自控成本的服主 |
| Managed Starter | 全托管 | $49 | 含约 5M tokens/月 | 中小服 |
| Managed Growth | 全托管 | $149 | 含约 20M tokens/月 + 天气/动物增值包 | 活跃大服 |
| 超量加购 | 任意托管档 | 按包 | 例如 +5M tokens / $X | 重度服 |

> 校准方法：取所选模型的输入/输出单价 × §3.2 的每回合 token 估算 → 反推每档的盈亏平衡额度，再留毛利。**[估算待补]**

## 4. 打包边界

| 组件 | 归属 | 部署形态 |
|---|---|---|
| hyperion 内核 + `persist.rs` + `Blocks` 编辑 API | **开源引擎** | 随源码 / crate 分发 |
| AI 插件层（`ai.rs` / `npc.rs` 桥接 + 配额/计费/防滥用） | **产品** | 自托管：随服务端二进制；托管：我们的镜像 |
| `hyperion-ai-agent` sidecar | **产品（壳）+ 私有（核）** | 独立进程/容器；workspace-excluded，自带 stable 工具链 **[事实]** |
| iacoder（agent loop / provider / 工具编排） | **私有** | 闭源，仅以编译产物或托管服务交付，**不开源、不随插件分发** |
| 天气/动物/步步生莲 | 增值/demo | 可选插件包 |

**许可 / 部署**：
- **自托管插件**：交付编译好的 hyperion+AI 插件 + sidecar 二进制（含 iacoder 编译产物），服主自带 LLM key。许可证需**禁止再分发 sidecar/iacoder 产物**以保护私有核。 **[假设]**
- **全托管 SaaS**：我们跑 sidecar + key + 配额，服主只连我们的端点；iacoder 永不离开我们的基础设施（最干净的护核方式）。

## 5. 最小可售里程碑（到"能收第一笔钱"）

按优先级（P0 = 不解决无法上线收钱）。

### P0 —— 阻断上线的硬编码债（代码已核实）
1. **`ai.rs:61` `DEFAULT_AGENT_BIN = "/Users/xudatie/.cargo/target/debug/hyperion-ai-agent"`** —— 写死个人绝对路径。**[事实]** 必须改为相对/可配置默认（`BEDWARS_AI_AGENT_BIN` 已存在但默认值是个人机器路径），否则在任何别的机器上 `/ai` 直接禁用。
2. **weather 全中文硬串**（`weather.rs:104/116` "天气恢复平静"/"暴风"/"地震"，`command/weather.rs` 多处"召唤…级暴风"等）。**[事实]** 若天气进任何售卖档需 i18n；不进则确保它不阻断核心路径。
3. **坐标与单张地图死耦合**：NPC spawn 写死 `(1.5,64,5.5)`（`npc.rs:39`）、动物 spawn 写死坐标表（`creatures.rs:46`）、weather 损毁 Y 段写死 `60..66/65..90`（`weather.rs:173`）。**[事实]** 这些都假设了那张 village 地图。MVP 至少要让 NPC/建造**不依赖特定坐标**（如基于玩家位置或配置出生点）。
4. **持久化与计费的最小闭环**：`persist.rs` 已具备原子落盘，但 **token 计费/配额/日限额尚不存在** —— 没有这层就无法"收费且不亏"。需新增：每玩家/每服 token 计量 + 配额拒绝路径。
5. **密钥与配置外置**：sidecar 已支持 `config.toml` + `${ENV:VAR}` **[事实]**，但需补**自托管安装文档**（怎么填 key、怎么指 binary 路径）。

### P1 —— 收钱必备的运营件
6. **计量与账单后端**：记录每次回合 token、按客户/服聚合、生成账单（托管档）。
7. **授权/license 校验**：自托管档需要 license key 校验，防止 sidecar/iacoder 产物被白嫖再分发。
8. **可观测性**：sidecar 已全量 stderr 日志 + 重启监督（`supervise`，最多 5 次崩溃放弃）**[事实]**，需补"AI 不可用"对客户可见的健康指标/告警。
9. **打包与分发**：自托管的一键安装（容器或脚本）；当前 sidecar 是 workspace-excluded 独立工具链 **[事实]**，需固化构建产物分发流程。

### P2 —— 增长/留存（非收钱前置）
10. 天气/动物增值包 i18n + 配置化，作为高价档点缀。
11. 全托管 SaaS 控制台（开关功能、查额度、加购）。
12. B2C 自营创意服（用同一产品自己当客户）。

### 收第一笔钱的最小路径
解决 **P0(1)(3)(4)(5) + P1(6)(7)** → 交付一个"自托管 Pro 档"插件包：服主自带 key、有日配额防爆、有 license 校验、有安装文档。这是边际成本最低、最快能验证付费意愿的形态。

## 6. 关键风险与未决项
- **token 单价是定价地基**，§3.4 数字全是占位，必须用真实模型单价 + 真实回合 token 实测校准。**[估算待补]**
- **自托管的私有核保护**：iacoder 编译产物随插件下发存在被逆向/再分发风险；若无法接受，应只走全托管。**[假设]**
- **多世界 / 多服伸缩**：当前 sidecar 一进程服务一个 hyperion 实例，多租户托管的进程/容器编排尚未设计。**[事实（单实例）] + [假设（需扩展）]**
- **AI 建造的安全边界**：当前无"建造区域权限"，AI 可改世界任意位置（受 fill 上限约束但无空间 ACL）。多人持久世界里需补防破坏。**[事实]**
